### 1.2 三个必须补的差异

**差异一：格子维，你求和、官方求平均**

```python
# 你写的
KL = F.kl_div(log_q, T_P, reduction="none").sum(dim=-1).mean(dim=-1)

# 官方（kd_loss.py:32-34）
kd_loss = F.kl_div(F.log_softmax(pred / T, dim=1), target,
                   reduction='none').mean(1) * (T * T)
```

实测（脚本第 1 步）：

```text
你的写法（格子维求和）      kl = 0.451223
官方写法（格子维求平均）    kl = 0.090245
比值 = 5.0   ← 正好等于格子数 5
```

**这不影响"学得对不对"，只影响"数值多大"**。因为 loss 最后要乘 `loss_weight`（官方 0.25），这个常数会被权重吸收掉。但如果你想复现论文的数字，就必须用 `mean`。

**差异二：温度**

官方的顺序是：**先把 logits 除以 T，再做 softmax / log_softmax，最后乘 T²**。

```python
target = F.softmax(soft_logits / T, dim=1).detach()      # ① 除 T 再 softmax
loss   = F.kl_div(F.log_softmax(pred / T, dim=1), target,
                  reduction='none').mean(1) * (T * T)     # ② 最后乘 T²
```

你的教师数据是概率，不是 logits，所以脚本里先用 `torch.log(T_P)` 反推一组等价的 logits（因为 `softmax(log(p)) == p`），再套官方公式。实测软化效果：

```text
T=1   教师分布 = [0.05, 0.1, 0.6, 0.2, 0.05]      ← 原样
T=2   教师分布 = [0.113, 0.159, 0.39, 0.225, 0.113]
T=10  教师分布 = [0.182, 0.195, 0.233, 0.209, 0.182]  ← 几乎平了
```

**为什么最后乘 T²**：除 T 之后梯度也被缩小了 T 倍，乘 T² 是把它补回来，这样换 T 不用重新调学习率。

**差异三：`detach()`**

你的 `T_p` 是个常量张量，天然没有梯度，所以不需要。官方的教师输出是前向算出来的，虽然外面包了 `torch.no_grad()`，但仍然显式 `.detach()` 一下——**这是防御性写法**：万一哪天有人把 `no_grad` 去掉了，也不会出现"梯度从教师流回学生"的严重 bug。

### 1.3 你代码里两个小问题（不影响理解，但值得知道）

**问题一：batch 对不上，靠广播蒙混过去了**

```python
T_p = ...            # (1, 4, 5)   batch = 1
S_l = torch.zeros(3, 4, 5, ...)   # (3, 4, 5)   batch = 3
```

PyTorch 会自动把 `T_p` 复制 3 份，所以能跑。但这是**静默广播**：如果哪天你把格子数写错（比如 `T_p` 是 5 格、`S_l` 是 17 格），它不一定报错，可能算出个莫名其妙的结果。

官方在 `kd_loss.py` 里第一行就是：

```python
assert pred.size() == soft_label.size()
```

**这种 assert 是廉价保险**，值得学。

**问题二：`T_l` 定义了但没用**

第 12 行 `T_l = torch.log(T_p)` 之后，只有注释掉的代码用到它。这是调试残留，删掉不影响运行。

## 2. 算法 1 逐行对照

### 2.1 首先解释一件事：你跑出全 0 是正常的

你当时跑的：

```python
anchors = [[2,3,4,6], [1,5,2,8], [1,4,7,5]]
gts     = [[2,5,6,8], [1,7,5,9]]
pos = 0.5, a = 0.5
X_new → 全是 False
```

**这不是 bug。** 这些框都只有几个像素大，彼此 DIoU 很低，而你的窗口是 `[a·pos, pos] = [0.25, 0.5]`，它们一个都落不进去。

这件事本身说明了一个关键问题：**固定阈值在真实数据上经常选不到东西**。不同大小的目标，anchor 的 IoU 分布完全不同；用一个固定的 0.5，对大目标可能太严、对小目标可能太松。

官方正是为了解决这个才用"自适应阈值"。

### 2.2 换一组能看出规律的数据

脚本第 2 步用 GT = `[20, 20, 60, 60]`（40×40 的目标）和一排逐渐偏移的 anchor，实测结果：

```text
自适应阈值 thr = 0.6809

 #     IoU    DIoU      你的固定阈值       官方自适应     角色
 0   1.000   1.000        不选           不选      正样本 → loss_ld
 1   0.681   0.672        不选           选中      VLR  → loss_ld_vlr
 2   0.471   0.443        选中           选中      VLR  → loss_ld_vlr
 3   0.325   0.271        选中           选中      VLR  → loss_ld_vlr
 4   0.220   0.138        不选           不选      背景（不学）
 5   0.143   0.032        不选           不选      背景（不学）
 6   0.047  -0.122        不选           不选      背景（不学）
 7   0.000  -0.360        不选           不选      背景（不学）
```

**这张表就是论文的核心。** 三件事一眼可见：

1. **0 号是正样本**（IoU 最高），走 `loss_ld`；
2. **1~3 号是"差一点"的区域**，走 `loss_ld_vlr`。它们数量多，才是定位蒸馏的主力；
3. **4 号以后彻底放弃**，因为位置太远，学它没意义。

### 2.3 四处差异

| | 你的实现 | 官方实现 | 为什么 |
|---|---|---|---|
| 阈值 | 固定 `pos=0.5` | 每个 GT 用"最像它的 topk 个 anchor"算 **μ+σ** | 大目标、小目标的 IoU 分布不同，固定值必然失效 |
| 区间系数 | `a=0.5` | `a=0.25` | 0.5 的窗口太窄，选不到足够的锚点 |
| 输出 | `(A, G)` 布尔矩阵 | 压成 `(A,)` 的 IoU 值 | loss 需要"每个锚点一个权重"，不是一个矩阵 |
| 实现 | 双重 for 循环 | 全向量化（广播） | 真实场景是 5115 个 anchor × N 个 GT，循环会慢到没法训练 |

第 3 条是你最需要跨过去的一步。官方的压缩规则是：

```python
# 某个 anchor 若落在多个 GT 的 VLR 里，取它和其中 IoU 最大的那个 GT 的 IoU
weighted = torch.where(mask, iou, 0)
vlr_value, _ = weighted.max(dim=1)     # (A, G) → (A,)
```

脚本里 `vlr_region()` 就是这个逻辑，你可以对照看。

第 4 条解释了"为什么官方代码那么难读"：**所有循环都变成了张量运算**。可读性换性能，这是检测代码的常态。

### 2.4 还有一个官方没做好的地方（顺便告诉你）

`atss_assigner.py` 的 `get_vlr_region` 里，如果某张图**没有 GT**（比如 VOC 里只含 difficult 目标的图），代码会走到第 203-216 行：

```python
if num_gt == 0 or num_bboxes == 0:
    ...
    return AssignResult(...)     # ← 返回的是个对象，不是 tensor！
```

但调用方的期望是拿一个 `(N,)` 的张量去做 `unmap`。所以**空标注图片会让训练崩掉**。

这不是你的问题，是官方代码的边界 bug。但知道它存在，以后遇到"训练到一半突然报 AttributeError"就有思路了。

## 3. 拼起来：你的两个练习 = 官方的 `loss_ld`

### 3.1 数据流

```text
你的练习1                     你的算法1
（KL 蒸馏）                   （VLR 区域）
    │                            │
    │  给"怎么比"                │  给"比谁"
    ▼                            ▼
┌────────────────────────────────────────────┐
│  官方 loss_single（ld_head.py:116-282）     │
│                                            │
│  pos_inds    ← 算法1 的正样本部分           │
│  remain_inds ← 算法1 的 VLR 部分（压缩后）  │
│  pred_corners/soft_corners ← 练习1 的 KL    │
│  weight      ← 算法1 压出来的 IoU           │
└────────────────────────────────────────────┘
```

### 3.2 官方代码里那四个变量，就是你练习里的东西

| 官方变量 | 是什么 | 你练习里对应 |
|---|---|---|
| `pos_inds` | 正样本的下标 | 你手写的 `pos_mask` |
| `remain_inds` | VLR 锚点的下标 | `calculate_val(...)` 的输出压成一维 |
| `pred_corners` | 学生分布 `(N*4, 17)` | 你的 `S_l` |
| `soft_corners` | 教师分布 `(N*4, 17)` | 你的 `T_p` |
| `weight_targets` | 每个锚点的权重 | 你练习里"全 1"的那个位置 |

### 3.3 跑一遍看数字

脚本第 3 步造了 80 个 anchor（两层特征图）和一个 40×40 的 GT，实测：

```text
anchor 总数      : 80
正样本数量       : 9    （IoU >= 阈值 0.3906）
VLR 锚点数量     : 46
背景数量         : 25

pred_corners 形状 : (36, 17)   = （9 个正样本 × 4 条边, 17 个格子）

loss_ld     = 1.197866   （正样本的定位蒸馏，avg_factor=4.0）
loss_ld_vlr = 1.072340   （VLR 区域的定位蒸馏，avg_factor=16.0）

自检：学生==教师时 loss_ld = -2.3e-07   ← 约等于 0，公式没错
```

几个可以自己验证的观察：

- **VLR 锚点（46）远多于正样本（9）**。这就是论文说的"定位知识主要来自 VLR"。
- **`avg_factor` 是写死的 4.0 / 16.0，不随样本数变**。所以正样本越多，`loss_ld` 越大。这是官方行为，不是笔误。
- **自检那行是负的 `-2.3e-07`**，因为浮点误差，理论上应该是 0。写测试时用 `abs(x) < 1e-5` 判断，不要写 `== 0`。
