致命

evaluate.py 架构与 checkpoint 不匹配 — 会直接崩溃

evaluate.py:42 实例化了 UNetNoSkip，但 evaluate.py:43 加载的 checkpoint 路径是 results/baseline/unet_cell_train_baseline.pth——这是 U_net_baseline.UNet（有 skip）的权重。

No-skip decoder 的第一个卷积输入通道数是 512，而 baseline 的是 1024（因为拼接了 skip），load_state_dict 直接抛出 RuntimeError：

RuntimeError: size mismatch for dec1.conv.double_conv.0.weight: copying a param with shape torch.Size([512, 1024, 3, 3]) from checkpoint, but the shape in current model is torch.Size([512, 512, 3, 3])

评估脚本在当前形态下根本无法运行。必须一一对应模型与 checkpoint。

致命

train_original.py 训练时关闭了数据增强

train_original.py:25 传入 is_train=False，导致 dataset_original.py 中所有增强（翻转、旋转）被跳过。仅用 18 张原始图训练 60 epoch，等效样本量极小。

对比之下，dataset_baseline.py 默认 is_train=True，baseline 和 no-skip 都自动开启了增强。这是导致 Original 退化的核心原因之一。

致命

无训练/验证划分 — 全部指标均为训练集内成绩

两个 dataset 类都把 01 和 02 两个序列的全部 18 张标注帧读入，训练脚本在这个全集上训练，evaluate 也在同一全集上评估。没有任何样本被留出做验证。

报告的指标无法反映泛化能力。在 18 张图上过拟合到 88% IoU 并不说明模型真的好，只说明它记住了这 18 张图。

致命

Original 用 SGD+高lr 训练导致退化，且无监控手段

train_original.py 使用 SGD(lr=0.01, momentum=0.99)。在仅 18 张图、无增强、无 BatchNorm 的条件下，这个优化配置很容易让模型陷入退化解。且脚本没有任何验证集监控、无 learning rate scheduler、无 early stopping——训练结束也不检查前景比例，退化无感知。

中等

加权损失缺少类别频率平衡项 w_c(x)

U-Net 论文公式为 w(x) = w_c(x) + w₀·exp(-(d₁+d₂)²/(2σ²))，其中 w_c(x) 是类别平衡权重，用于补偿前景像素远少于背景的问题。

losses_original.py:113-115 将基础权重硬编码为 1.0，省略了 w_c(x)。在不平衡数据上，背景主导梯度方向，模型倾向预测背景或反之在 loss 被边界项主导时可能翻转为全前景。这是加权 loss 也未能阻止退化的原因之一。

为什么去掉 skip connection 精度反而更高？

分析

当前条件下无法得出"skip 无用"的结论

  • 数据量极小：仅 18 张图，且是训练集内评估，不是泛化指标。
  • 模型结构不同：No-skip 版本 同时 加入了 BatchNorm，所以你比较的不仅是"有无 skip"，而是"有 BN + 无 skip" vs "有 BN + 有 skip"。BatchNorm 本身就是强正则化器。
  • 参数更少：No-skip 约 27.9M vs Baseline 约 31.0M，在极小数据集上参数少的模型可能恰好正则化得更好。
  • 单随机种子：88.36% vs 86.31% 的差距不到 2%，很可能在不同 seed 下逆转。至少需要 3–5 个种子的均值±标准差。
  • 无验证集：两个数字都是在训练数据上的表现，不能说明谁泛化更好。

要验证 skip 的作用，应控制 BN、优化器、损失完全相同，只改变 skip 的有无，在独立验证集上、多个种子下评估。

修复建议（优先级排序）

  1. 修复 evaluate.py：按实验组分别加载对应模型架构和 checkpoint。Original → U_net_original.UNet，Baseline → U_net_baseline.UNet，No-Skip → UNetNoSkip。
  2. 开启 Original 训练增强：将 train_original.py:25 的 is_train=False 改为 is_train=True。
  3. 划分训练/验证集：建议用 Seq01 的 9 帧训练、Seq02 的 9 帧验证，避免同序列时序相邻帧泄漏。每个 epoch 结束后在验证集上计算 IoU。
  4. 加入训练诊断：每个 epoch 记录预测前景比例、验证集 IoU。如果前景比例 > 95%，立即报警（退化信号）。
  5. 补齐 w_c(x)：在 WeightedCrossEntropyLoss 中加入类别频率平衡权重，如 w_c(fg) = N_bg / N_total, w_c(bg) = N_fg / N_total。
  6. 控制变量做公平对比：如果想测试 skip 的作用，保持 BN、Adam、CE+Dice、增强完全相同，只改变 skip 的有无，在验证集上、3+ 种子下报告均值±标准差。
  7. Original 分支调优：如果目标是严格论文复现，先开启增强，考虑加 BatchNorm（或用论文的 weight init），用更保守的 lr（如 0.001）和梯度裁剪，加入 lr scheduler。
验证方法：通过实际加载 checkpoint 做前向推理确认了 Original 两个模型的全前景退化（前景比例 100%），以及 evaluate.py 加载错误架构导致的 RuntimeError。数据集统计：Seq01 含 9 帧标注（man_seg002/005/021/031/033/034/039/054/067），Seq02 含 9 帧标注（man_seg006/007/014/027/034/038/042/061/067），合计 18 帧。
