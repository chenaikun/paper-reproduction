# Part 1 论文解决了什么问题

## 1.1 背景一句话

医学图像分割 = 给图像里的**每一个像素**做分类:这个像素属于"细胞"还是"背景"。
输出不是"这张图里有细胞"这样的标签,而是一张和原图一样大的"涂色图"(掩膜)。

> 通俗类比:目标检测是"在照片上画框框住猫",分割是"沿着猫的轮廓一像素一像素抠出来"。

## 1.2 痛点一:数据少

深度网络需要大量标注数据,但医学图像的像素级标注必须由专业人员逐帧手描:
本项目用的 DIC-C2DH-HeLa 数据集(细胞追踪挑战赛),两个序列各 512×512,只有 **9+9=18 帧**有标注。
所以核心问题是:**如何在极少量标注下训练出精确的像素级分割网络?**

## 1.3 痛点二:一对矛盾

分割同时要求两件事,而它们天然冲突:

| 要求 | 需要什么 | 代价 |
| :--- | :--- | :--- |
| 理解"这是细胞"(语义/上下文) | 大感受野 → 层层下采样 | 空间细节丢失 |
| 知道"细胞边界在哪一像素"(定位) | 高分辨率特征图 | 感受野小,看不全 |

> 类比:把一张地图不断缩小复印,你能看清全国格局(上下文),但看不清小巷(细节);
> U-Net 的解法是:缩小的每一份原图都留着(跳跃连接),放大还原时逐层"贴回去"。

**U-Net 的答案:编码器负责"理解",解码器负责"还原",跳跃连接把两边的优势拼起来。**
这篇论文还有第二个贡献:针对"相邻细胞中间那条缝"设计的加权损失(见 2.5)。

# Part 2 使用了什么方法,代码如何写的

## 2.1 论文方法总览(对应你笔记的 Section 2)

```
输入 512×512 灰度图
   │
   ▼
┌─────────────── 编码器(收缩路径) ───────────────┐
│  DoubleConv(64)  ──skip1──┐                      │
│  MaxPool↓2 → DoubleConv(128) ──skip2──┐          │
│  MaxPool↓2 → DoubleConv(256) ──skip3──┐          │
│  MaxPool↓2 → DoubleConv(512) ──skip4──┐          │
│  MaxPool↓2 → DoubleConv(1024)  ← 瓶颈层         │
└─────────────────────────────────────────────────┘
   │ 上采样(Cat skip4) → DoubleConv(512)
   │ 上采样(Cat skip3) → DoubleConv(256)
   │ 上采样(Cat skip2) → DoubleConv(128)
   │ 上采样(Cat skip1) → DoubleConv(64)
   ▼
1×1 Conv(64→2) → 输出 324×324×2 (每个像素两个类别的得分)
```

三个关键设计:
1. **DoubleConv**:每级两个 3×3 卷积 + ReLU,扩大感受野、增强非线性;
2. **跳跃连接(skip connection)**:编码器下采样前的特征图,拼接到解码器同分辨率处;
3. **valid conv(不补边)**:每层特征图缩小,最终输出只有中间 324×324 —— 这部分像素的
   感受野是完整的,不依赖"编造"的边缘信息。**这正是为什么掩膜要中心裁剪到 324**(见 2.3)。

## 2.3 一张图从硬盘到损失值(数据流水线,汇报重点)

**这是本项目最容易被问住、也最能体现"读懂了论文"的一段:**

```
原图 t002.tif (512×512 灰度)          标注 man_seg002.tif (512×512, 每细胞一个编号)
        │                                       │
        │  /255 归一化 → [1,512,512] Tensor      │  ①增强(翻转/旋转/弹性,同步做)
        │                                       │  ②二值化(>0 → 0/1) + instance 保留
        │                                       │  ③中心裁剪 [324,324]
        ▼                                       ▼
   模型输入(不裁剪!)                      模型标签(裁到 324)
        │                                       │
        └────────────► U-Net (valid conv) ◄─────┘
                          │
                          ▼
              输出 [1, 2, 324, 324]  ← 512 进 324 出,每边自然裁掉 94 像素
                          │
              argmax → 每像素类别 → 与标签算损失
```

**关键问答:为什么图像不裁、掩膜裁到 324?**
因为 valid conv 不补边,网络"中间 324×324 区域"的输出,其感受野才完全落在真实图像内;
512−324 = 188,每边 94,恰好与中心裁剪(每边裁 94)对齐。**图像与掩膜在空间上是严格对齐的**,
这不是 bug,而是论文原设计(论文里 572 进 388 出,同一个思想)。
我们曾实测验证:512 输入 → 输出恰好 324×324 ✅。

**为什么增强要同步做、掩膜旋转要用最近邻插值?**
图像和掩膜必须做**同一个**几何变换,否则像素和标签错位;
掩膜是类别编号(0/1),双线性插值会产生 0.5 这种"半个细胞"的非法类别,所以用最近邻。

## 2.4 损失函数:三个层次(对应代码 `losses_Dice.py`、`losses_original.py`)

**① 交叉熵 CE(逐像素分类):** 每个像素是一个二分类问题,`nn.CrossEntropyLoss` 直接用;
输入是 logits(未经 softmax 的原始得分),内部自带 softmax。

**② Dice 损失(区域重叠):** 衡量预测掩膜和真实掩膜的重叠程度,公式
`Dice = 2|A∩B| / (|A|+|B|)`,loss = 1−Dice。
对类别不平衡不敏感(背景像素再多也不影响它),代码里加了 `smooth=1e-5` 防止除零。

**③ 论文加权 CE(本项目实现最复杂的一个):**

```
w(x) = w_c(x) + w₀ · exp( −(d₁(x)+d₂(x))² / (2σ²) )
```

- `w_c(x)`:类别平衡权重,`w_c(前景)=背景占比`,`w_c(背景)=前景占比`——少数派权重大;
- `d₁, d₂`:该像素到**最近**和**第二近**细胞的距离(用 `scipy.ndimage.distance_transform_edt`
  距离变换算出);两个细胞中间的缝隙处 d₁+d₂ 最小,权重指数级升高;
- `w₀=10, σ=5` 为论文取值。
- **实现要点**:距离变换在 CPU 上逐样本计算(所以加权 CE 训练更慢),这就是为什么数据集要
  额外返回 instance mask——没有"每个细胞一个编号",就算不出每个细胞的距离场。

> ✍️ 可以这样讲:普通 CE 对"两个贴在一起的细胞中间那条缝"一视同仁,而论文给这条缝的像素
> 乘上最高权重,强迫网络学会把粘连的细胞分开——这是这篇文章在损失设计上最独特的贡献。

## 2.5 训练循环骨架(所有训练脚本共用的 10 行核心)

```python
for epoch in range(num_epochs):          # 把 9 张训练图完整过一遍 = 1 个 epoch
    for images, masks in dataloader:     # batch_size=1 → 每 epoch 9 次迭代
        optimizer.zero_grad()            # 清掉上一轮的梯度
        outputs = model(images)          # 前向: [1,2,324,324] 的 logits
        loss = criterion(outputs, masks) # 算损失
        loss.backward()                  # 反向传播算梯度
        optimizer.step()                 # 用梯度更新权重
```

`train_ablation.py` 在此之上加了工程化包装(值得学习并带到以后所有实验里):

1. **参数化配置**:模型/优化器/损失/lr 全部变成命令行参数,一次只改一个变量;
2. **固定随机种子**(`seed=42`):保证实验可复现;
3. **每个 epoch 在验证集上评估**,按验证 IoU 保存 `best_model.pth`(而不是盲目用最后一轮);
4. **退化监控**:前景比例 >0.95 立即报警——本项目最重要的防线;
5. **日志落盘** `log.txt`:每个实验的完整轨迹可追溯。

## 2.6 评估脚本设计(`evaluate.py`)

`EXPERIMENT_REGISTRY` 字典:实验名 → (模型类, checkpoint 路径, 是否需要 instance mask),
对 `step*` 实验还能从名字自动推断架构。**价值:评估时绝不能加载错架构**——
本项目最初的 `evaluate.py` 就犯过"用 no-skip 架构加载 baseline 权重"的错误,直接 shape mismatch 崩溃。

# Part 3 如何想到的、如何思考

> 这是导师第三点要求,也是汇报的灵魂。分两层:论文作者怎么想到的(读书层次),
> 以及**我们这周怎么思考的**(科研层次,更有含金量)。

## 3.1 论文作者的思考链(设计是如何被逼出来的)

```
观察:下采样能扩大感受野(看得懂),但丢失空间细节(定不准)
  ↓ 矛盾
医学分割恰恰既要看得懂、又要定得准
  ↓ 设计
两条路:编码器管"看得懂",解码器管"定得准"
  ↓ 新问题
解码器上采样恢复的细节是"猜"出来的,不可靠
  ↓ 设计
跳跃连接:把编码器每一层的高分辨率特征直接"抄近道"送给解码器
  ↓ 新问题
相邻细胞粘连,普通 CE 分不开那条缝;标注只有 18 帧
  ↓ 设计
边界加权损失(逼网络学缝隙)+ 大量数据增强(弹性变形"无中生有"造数据)
```

> ✍️ 一句话总结:**U-Net 不是天才灵光,而是每个设计都对应一个具体的失败模式。**
> 读论文的方法:先找到"它解决了什么失败",再去看"它用什么结构解决"。

## 3.2 我们的复现思考链(真实科研过程,汇报的高潮部分)

**第 1 步:复现 baseline,数字很好看 → 保持警惕**
BN + Adam + CE+Dice,18 帧全集训练全集评估,IoU 93.56%(未增强)/ 86.31%(增强后)。
**疑点**:未增强反而更高?——因为在背训练集(过拟合),指标还是"训练集内成绩",不代表泛化。

**第 2 步:复现论文原方案,结果异常 → 起疑心**
按论文配置(无 BN + SGD 0.01/mom 0.99 + 加权 CE)训练,IoU 67.89%;
**加上加权损失后指标纹丝不动**——"某个组件没起作用"通常是重大警讯。

**第 3 步:诊断:不迷信数字,亲手查证据(5 连问)**
1. 这个指标是怎么算的?→ 查出训练/验证没划分,67.89% 是 18 帧全集内成绩;
2. 模型预测到底长什么样?→ **载入 checkpoint 逐帧推理:预测前景率 100%,18 张图全是全白**;
3. 67.89% 意味着什么?→ 实测:标注前景占比恰好 ≈67.9%——**模型啥也没学会,只是"全选C"**;
4. 为什么"全选C"也能得 67.89?→ 因为前景是大类,平凡解自动获得等于类别占比的 IoU;
5. 训练配置公平吗?→ 查出 Original 关了增强、无验证集、batch 不同、多变量混杂。

**第 4 步:提出假设,设计受控消融**
假设池:优化器太激进?损失不对?没增强?架构缺 BN?——**每次只改一个变量**,
统一流水线(Seq01 训练/Seq02 验证、同 batch、同 seed、每步监控退化),Step 0→5 逐步逼近论文。

**第 5 步:结果出乎意料,追加补救对照把结论钉死**
Step 4(去 BN)不是"变差"而是"坍缩";于是追加 5 组对照:
降 10 倍学习率、动量降到 0.9、换 Adam、Adam 再降 10 倍、加弹性变形——**全部坍缩**。
同时用"全前景本底 IoU"实测(73.52%)验证了所有这些数字都是平凡解。
**结论收敛:唯一决定性变量是 BatchNorm。**

**第 6 步:机制解释(知其所以然)**
无 BN 时深层网络激活值逐层漂移放大,logits 迅速饱和 → 梯度消失 → 锁死在多数类平凡解;
BN 每层把激活"归一化",梯度通道始终畅通。9 帧小数据放大了这一切。

> ✍️ 这条链的价值不在结论,而在**每一步的思考动作**:
> 结果反常 → 先怀疑测量(指标怎么算的)→ 再看原始输出(别只看 loss)→ 提假设 → 单变量验证 →
> 反直觉就加对照 → 给机制解释。以后做任何方向都用得上。

## 3.3 从本实验沉淀的科研习惯清单

1. **数据到手先体检**(早期写过 check_bug 小脚本,思想保留):打印数值范围、标签唯一值、前景占比;
2. **模型搭好先过形状**:随手写十几行,用一张假数据跑通 forward 再开训练;
3. **每个实验必须有验证集**,训练集内的指标不算数;
4. **给训练加"体检仪"**:前景率这种 sanity check 要进训练循环,退化当场报警;
5. **"没变化"和"变差"都是信号**:组件加了没效果,先确认它真的生效了(旧加权 loss 实验
   指标不变,不是加权没用,是模型已经死了);
6. **一切落盘**:log、config、seed、checkpoint,以后翻旧账全靠它们。

| 9 | 补救:换 Adam 5e-4 | 74.27%* | ⚠️ 退化 |
| 10 | 补救:Adam lr 降 10 倍(1e-4) | 73.52%* | ⚠️ 退化 |

\* 73.52% 是**全前景平凡解在 Seq02 上的本底 IoU**(实测验证),无分割能力。
无 BN 实验全部在第 2~4 个 epoch 内坍缩,59/60 个 epoch 前景率 >0.95,此后从未恢复。

## 4.2 三条结论

1. **BatchNorm 是决定性因素**:Step 9 与 Step 1 唯一差别是去 BN,结果从 88.56%(健康)变坍缩;
   且无 BN 在 5 种优化器配置下全部失败——不是超参问题,是架构可训练性问题。
2. **旧实验的 67.89% 之谜破解**:它就是全前景平凡解在 18 帧全集上的本底占比,
   "加权损失无效"的真相是模型已经死了,加权救不了死模型。
3. **论文组件不是都要照抄**:Dice 可去(87.25→88.56),SGD 在 BN 在场时可行(86.61),
   弹性变形在本数据规模下无可测增益。**完整复现论文方案需要论文量级的数据与配套
   (deep supervision 等),9 帧标注条件下,Baseline(BN+Adam+CE)是稳定且更优的选择。**

# Part 5 科研实验方法论(举一反三,重点准备)

> 这部分回答"以后科研做实验有什么启发"。三个替换策略 + 一张速查表 + 一套消融规范。

## 5.1 优化器替换策略

| | SGD | SGD + Momentum | Adam |
| :--- | :--- | :--- | :--- |
| 学习率敏感度 | 高 | 高(但更快) | 低,自适应 |
| 调参成本 | 大 | 大 | 小 |
| 收敛速度 | 慢 | 中 | 快 |
| 泛化(大量数据+好调参时) | 好 | 好 | 略逊 |
| 适用场景 | 大数据大 batch 精调 | 论文复现、追求极限 | **默认首选** |

- **决策**:新任务先用 Adam(1e-4~5e-4)跑通;要冲性能或复现论文再换 SGD 精调。
- **有效学习率概念**:momentum 的惯性使实际步长 ≈ `lr/(1−momentum)`。
  论文配置 0.01/(1−0.99)=**1.0**,非常激进——有 BN 时没事(Step 2 正常),
  没 BN 时必死。**换优化器前,先弄清稳定性问题的来源,别把架构的锅甩给优化器。**

## 5.2 损失替换策略(按"错误长什么样"选损失)

| 你观察到的错误 | 该换什么损失 |
| :--- | :--- |
| 分类错、概率不准 | 交叉熵 CE(基础款) |
| 小目标/少数类漏检,背景吞掉前景 | 加权 CE、Focal Loss |
| 预测"糊成一片"、轮廓差、区域大小不对 | Dice / IoU 损失 |
| 相邻目标粘连、边界不清 | 论文式边界加权(本项目已实现) |
| 类别极度不平衡 | Dice 系 / Focal / 加权,通常组合使用 |

- **本项目证据**:二类细胞分割上 Dice 并非必需(Step 0→1,87.25→88.56);
  加权 CE 在 BN 在场时反而略降(84.41)——小数据上边界项可能主导梯度。
  **教训:论文里的组件要逐个验证必要性,不要默认"论文写的都必须上"。**

## 5.3 学习率策略(最重要的单个超参)

1. **先扫量级再精调**:按 log 尺度试 {1e-4, 5e-4, 1e-3, 1e-2},差一个量级天壤之别;
2. **看 loss 曲线定 lr**:一直不降→太小;爆炸/NaN→太大;剧烈震荡→偏大或 batch 太小;
3. **进阶调度**:warmup(开头小步走防炸)+ cosine/step decay(后期小步精修)——
   本项目还没用调度器,是明确的下一步改进项;
4. **有效学习率**:改 momentum 等效于改步长,两者不要同时乱调(一次一个变量);
5. **本项目的反例教育**:无 BN 时 lr 从 0.01 降到 1e-4(100 倍)全部坍缩——
   **调参救不了的病,是架构/数据的病。先找结构性原因,再调超参。**

## 5.4 "看现象 → 做什么"速查表(最实用的举一反三)

| 现象 | 先怀疑什么 | 动作 |
| :--- | :--- | :--- |
| loss 一步都不降 | 数据/标签错了;lr 太小 | **先查数据**(check_bug 思想),再调 lr |
| loss = NaN / 爆炸 | lr 太大;无归一化 | 降 lr;加 BN/归一化;梯度裁剪(治标) |
| loss 剧烈震荡 | lr 大;batch 小 | 降 lr;增大 batch |
| 训练集好、验证集差 | 过拟合(背题) | 增强、正则、早停、更多数据 |
| 训练验证都差 | 欠拟合 | 加容量、训久、检查标签质量 |
| **指标 ≈ 某类占比** | **退化为平凡解** | 打印预测分布/前景率,立刻停下分析 |
| 加了组件指标不变 | 组件没生效;或模型已退化 | 单独验证组件;加监控 |
| 结果好到不真实 | 数据泄漏/训练集内评估 | 检查划分!这是新手最常见错误 |

## 5.5 消融实验设计规范(以后每个实验都按这个来)

1. **单变量原则**:一次只改一个东西(本项目 11 组实验的立足点);
2. **固定随机种子**,并做 3~5 个种子报均值±方差(单种子差距 <2% 不可信,如旧 no-skip 实验);
3. **验证集与训练集物理隔离**(跨序列划分,避免相邻帧泄漏);
4. **同 batch/同 epoch/同增强**,否则对比不公平(旧三组实验的教训);
5. **记录一切**:config、log、checkpoint、git commit——本项目用 `results/step*/log.txt` 落实。

# Part 6 名词通俗词典(组会被问到直接翻这里)

## 架构类

- **BatchNorm(BN)**:每层输出先按 batch 统计做标准化(均值0方差1)再过 ReLU。
  类比:传话游戏每传一手就把音量调回正常,防止越传越大声。**本项目主角:去掉它模型直接失控。**
- **valid conv(不补边卷积) vs padding conv**:valid 不在图像边缘补 0,每层特征图缩小 2 像素;
  padding 补 0 保持尺寸。valid 的好处是输出只依赖真实像素,坏处是要单独处理尺寸对齐(掩膜裁 324)。
- **跳跃连接(skip connection)**:把编码器高分辨率特征直接拼给解码器同层。
  类比:把缩小的地图复印时,每一层缩印件都留着,放大还原时逐层贴回去。
- **转置卷积(up-conv / ConvTranspose2d)**:可学习的"放大 2 倍"操作,让特征图变大。
- **感受野**:输出图上一个像素"回头能看见"多大范围的原图。
- **logits / softmax / argmax**:logits 是网络最后一层未归一化的原始得分;softmax 把得分变成
  概率;argmax 挑概率最大的类别作为最终答案(预测图就是这么来的)。
- **instance mask vs binary mask**:前者每个细胞一个编号(1 号细胞、2 号细胞…),
  后者只有前/背景两类。算边界距离场必须用 instance mask。

## 训练类

- **epoch / batch / iteration**:把 9 张训练图完整过一遍 = 1 个 epoch;batch_size=1 表示一次喂 1 张;
  每 epoch 迭代 9 次。
- **学习率(lr)**:每次权重更新的步子大小。太大一步跨过头,太小磨蹭到天荒地老。
- **momentum(动量)**:更新时保留一部分上次的移动方向。类比:重球滚下山坡,有惯性,
  能冲过小坑(局部抖动)。**有效学习率 ≈ lr/(1−momentum)**,所以 0.99 的动量让 0.01 的 lr
  实际步长≈1.0。
- **梯度裁剪(grad clip)**:梯度太大时强行截断。类比:刹车。治标不治本(本项目 Step 4-8 证明了)。
- **过拟合**:把训练集"背"下来了而不是学会规律。类比:背课文 vs 理解课文;一到新考题就露馅。
  表现:训练集分高、验证集分低。
- **数据增强 / 弹性变形**:用翻转旋转等变换"无中生有"造训练样本;弹性变形是把图像想成
  印在橡皮膜上随机拉扯——细胞形态本身多变,所以特别适合。
- **随机种子(seed)**:固定洗牌方式,让实验可复现。本项目全部 seed=42。
- **训练/验证/测试集**:平时作业/模拟考/高考。用模拟考(验证集)选模型,绝不拿高考题(测试集)调参。

## 指标类

- **IoU(交并比)**:预测区域 ∩ 真实区域 / 预测区域 ∪ 真实区域。两个圈重合得越彻底越接近 1。
- **Dice**:2|A∩B|/(|A|+|B|),和 IoU 同族,分割任务最常用,永远 ≥ IoU。
- **前景率(fg_ratio)**:预测图里"白像素"的比例。它是本项目的**退化报警器**。

## 实验方法与现象类(汇报最容易被问的词)

- **消融实验(ablation study)**:把系统当成积木,一次拆一块,看性能掉不掉——掉得狠的就是命根子。
  本项目 11 组实验就是一场系统的大消融。
- **baseline(基线)**:参照组。所有改进都要和它比,且只能在它身上"一次改一处"。
- **平凡解 / 退化解**:模型没学会任何规律,输出一个常数答案(全白/全黑)躺平。
  类比:考试不会做,答题卡**全选 C**——如果标准答案里 C 占 73.5%,它能"白嫖"73.5% 的分。
- **全前景退化**:本项目实锤的现象:无 BN 架构第 2 个 epoch 就输出全白图,IoU 恒等于
  前景占比(Seq02 上 73.52%,18 帧全集上 67.89%)。**识别方法:看预测前景率是否 ≈ 某类占比。**
- **跨序列验证**:Seq01 的 9 帧训练、Seq02 的 9 帧验证。两个序列是不同批次拍的(存在"域差"),
  这比随机划分严格得多,防"相邻帧几乎一样"的数据泄漏。
- **deep supervision**:论文对解码器中间输出也加辅助损失,像老师中途检查草稿纸。本项目未实现,
  属于"完整复现论文"的剩余工作。

# Part 8 答辩 FAQ(预演)

**Q1:为什么用 valid conv 而不是 padding conv?**
忠于论文原设计;且 valid conv 的输出场(324×324)只依赖真实像素,医学上更保守。
代价是掩膜要中心裁剪对齐(2.3 节),我们实测过 512→324 的严格对齐。

**Q2:skip connection 真的有用吗?你们 no-skip 反而 88.36% > 86.31%?**
那是旧实验:全集内评估 + 单种子 + BN 两个版本都有,差距 <2% 不可信。
正确做法(我们已在做):控制 BN/优化器/损失全同,跨序列验证,多种子——再下结论。

**Q3:为什么加 BN 之后 SGD(momentum 0.99)就稳了?**
BN 让每层激活分布稳定,梯度不会随层数放大/消失;我们的证据:BN 在场时有效学习率≈1.0
都能正常收敛(Step 2),无 BN 时连 Adam 1e-4 都坍缩(Step 10)。

**Q4:Dice 损失不是分割标配吗,为什么去掉更好?**
在二类、前景占比不极端的任务上 CE 足够;Dice 的价值在极端不平衡和多类小目标。
这正说明"组件必要性要逐个验证"。

**Q5:一周时间线?**(可配 git log 展示)
搭建数据集与 baseline → 复现论文原架构(SGD+CE)→ 加权损失 → no-skip 对照 →
发现异常并系统诊断(diagnosis.html)→ 重写统一流水线 → 11 组受控消融 → 定位根因(BN)。

**Q6:最大的收获?**
"指标好看"和"模型正确"是两回事;以及一套可复用的实验方法:先怀疑测量、再看原始输出、
单变量验证、反直觉加对照、给机制解释。
