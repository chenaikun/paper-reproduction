## 2. 本例配置

采用 README 中的 CIFAR-100 四教师实例：

~~~text
student = ShuffleV2
teachers = [RegNetY_400MF, RegNetX_400MF, resnet32x4, wrn_28_4]
C=100, M=4
常规batch设置B=64；本次CPU追踪B=2
kd_T=4, feat_weight=5
~~~

后面的 B 可替换成64。**四个教师的顺序固定**，它同时决定 state 的拼接位置和 action 列的含义。

## 3. 学生网络前向：为什么有 feature list

调用 models/ShuffleNetv2.py:140–160 的 model(x,is_feat=True)：

| 返回项 | 形状 | 作用 |
|---|---|---|
| 输入 | [B,3,32,32] | RGB 图片 |
| features[0] | [B,24,32,32] | 初始卷积输出 |
| features[1] | [B,116,16,16] | 第一个 stage |
| features[2] | [B,232,8,8] | 第二个 stage |
| features[3]，即 features[-2] | [B,1024,4,4] | 本代码用于 feature KD 的空间特征 |
| features[4]，即 features[-1] | [B,1024] | 全局池化后的向量 |
| logits | [B,100] | 分类层原始分数 |

注意 features[-2] 不是“倒数第二个 stage 的232通道图”。它是该函数返回列表的倒数第二项，即1024通道的最终空间特征。

## 5. 特征对齐：一份学生图变成四份

学生原图 [B,1024,4,4]，教师是8×8，通道分别384/256。

TransFeat 为每位教师创建独立 Embed。此配置先用双线性插值把4×4扩大到8×8，然后用1×1卷积、BN、ReLU变换通道：

~~~text
学生空间图 [B,1024,4,4]
  → bilinear interpolate → [B,1024,8,8]
  ├─ Embed0: Conv1x1(1024→384)+BN+ReLU → [B,384,8,8]
  ├─ Embed1: Conv1x1(1024→384)+BN+ReLU → [B,384,8,8]
  ├─ Embed2: Conv1x1(1024→256)+BN+ReLU → [B,256,8,8]
  └─ Embed3: Conv1x1(1024→256)+BN+ReLU → [B,256,8,8]
~~~

适配器是可训练的，和学生一起被加入 optimizer。学生的两份384通道结果虽然同形，参数独立；不是复用同一份适配结果。

注意源码 TransFeat.forward 在教师循环里会重赋值 feat_s。这个四教师例子目标都是8×8，所以空间大小一致；不能把此流程未经检查推广到任意混合分辨率教师。

## 6. get_agent_state：准确的结构不是一个大 tensor

先把四份对齐学生图分别全局平均池化，得到 [B,384]、[B,384]、[B,256]、[B,256]。与对应教师 embedding 算 cosine。

逐教师：

~~~text
feat_cos_sim = [B,1]
logit_kl     = [B,1]
teachers_ce  = [B,1]
t_embedding  = [B,d_m]
t_logits     = [B,100]

teacher_info = cat([cos, KL, CE, embedding, logits], dim=1)
~~~

得到：

~~~text
teacher_infos = [
  Tensor[B,487],        # 384+100+3
  Tensor[B,487],
  Tensor[B,359],        # 256+100+3
  Tensor[B,359]
]
t_ces         = Tensor[B,4]
t_s_logit_div = Tensor[B,4]
t_s_feat_div  = Tensor[B,4]

agent_state = (teacher_infos, t_ces, t_s_logit_div, t_s_feat_div)
~~~

这是“tuple里含一个异宽tensor list和三个tensor”，不能笼统标成 [B,4,487]。三类标量既进入 learned 分支的拼接，也单独返回供规则支路使用。

所有返回信息都 detach。state 保留当前师生信息的数值，但切断其反向计算图。

## 7. PolicyTrans：1692→128→两个4

models/policy.py 中的具体形状：

~~~text
cat(teacher_infos, dim=1): [B,1692]
Linear(1692,128,bias=False): [B,128]
ReLU: [B,128]
├─ logit_head: Linear(128,4)+Softmax(dim=1)  → Wgen_l[B,4]
└─ feature_head: Linear(128,4)+Softmax(dim=1)→ Wgen_f[B,4]
~~~

隐藏层128维已在本次原始模块运行中核实；前一轮精读未核实这一点，不能仅凭旧笔记认定该细节。

规则支路：

~~~python
Wconf = (1 - softmax(t_ces, dim=1)) / (M - 1)
Wdiv_l = softmax(t_s_logit_div, dim=1)
Wdiv_f = softmax(t_s_feat_div, dim=1)
~~~

全部为 [B,4]。

- dynamic=False：两个 final head 各自对三条分布做平均。
- dynamic=True：两组长度3的可训练参数分别 softmax 后作为三支路融合系数。初始化全1，故初始比例仍各1/3。

README 的运行命令开启 dynamic；PDF 默认写固定1/3。讲论文默认方法和讲 README 运行示例时应分别说明。关闭 dynamic 仍有逐样本教师权重，只是不学习这两个全局三支路混合比例。

## 8. 第0个 epoch：实际是全1权重

train_loops.py:241–243 将 epoch==0 的两套 action 覆盖为全1：

~~~text
Wl=Wf=ones([B,4])，每行和为4
~~~

后续 epoch 输出归一化权重，每行和为1。因此 RL 入口的预热 KD 总尺度相对后续阶段不同。

另一个 train_avg 函数把四教师损失除以4，但 train_student_rl.py 导入并调用的是 train，而不是 train_avg。不能用 train_avg 的平均方式替论文 RL 入口解释预热。

## 9. 学生损失：unreduce=True 是关键

utils.DistillKL：

~~~text
student log_softmax(logits/T) [B,100]
teacher softmax(logits/T)     [B,100]
KL元素值×T²                   [B,100]
sum(class)                    [B]
~~~

FeatureMSELoss：

~~~text
两份已对齐的[B,Cm,8,8]
→ flatten [B,Cm*64]
→ 差平方 → mean(channel*space)
→ [B]
~~~

每位教师：

~~~python
loss_kd += mean(Wl[:,m] * KL_m)       # [B]*[B]→mean→scalar
loss_feat += mean(Wf[:,m] * MSE_m)
loss = mean(CE) + loss_kd + 5*loss_feat
~~~

α在该路径中相当于1。parser 虽有 ce-weight、kd-weight，这里的总损失并没有把它们作为乘子；不能看到参数名就认为参数一定生效。feat_weight 则确实被使用。

学生反向阶段 action 在 no_grad 中生成并 detach，state也detach。因此：

| 模块 | 本阶段是否产生梯度 |
|---|---|
| 学生 | 是 |
| 四套特征适配器 | 是 |
| 教师 | 否 |
| agent | 否 |

## 10. Reward：代码比较样本，不比较同一图片的教师

train_loops.py:277–288：

~~~python
reward = -(CE_per_sample
           + sum_m(Wl[:,m] * KL_m)
           + 5 * sum_m(Wf[:,m] * MSE_m))          # [B]
normalized = (reward - reward.mean()) / reward.std()
normalized = clamp(normalized.detach(), 0, 1)    # [B]
~~~

它给 batch 中负损失较高、也就是总损失较低的样本非零权重；较低 reward 被截成0。不是每张图四位教师各自得到四个正负 reward。

源码没有在 std 分母加 epsilon。reward 全部相等、或 B=1 等退化情况需要另行处理；这说明该路径存在数值边界，不代表本次 B=2 随机追踪已出现该问题。

**反馈时点：** 源码在 optimizer.step() 后执行上述几行，但 logits 和 trans_student_features 都来自 step 前的 forward，中间没有重新前向。因此这些数值并不是参数更新后模型的重新测量，更不是“训练前后改善量”。执行顺序在后，张量内容仍是旧快照。

## 11. 缓存和交替训练时机

每个 batch 缓存：

~~~text
state：tuple(list of 4 tensors + 3 matrices)
两套action：[B,4]
reward：[B]
~~~

agent_step 默认1000。训练循环在 batch_idx 为非零且能被 agent_step 整除时更新一次 agent；之后清空这段历史。剩余历史在 epoch 末尾更新。因此默认情况下，如果一个 epoch 不到1001个 batch，就在 epoch 尾部更新。若调小 agent_step，也会在 epoch 内更新；不能把所有配置都描述成“每个epoch只交替一次”。

## 12. Agent 的真实目标：reward 加权全1 BCE

train_agent 原始函数接收缓存的旧 actions，但更新目标并没有用旧 actions 作标签或计算其 log 概率。它重新调用 agent(state)，然后：

~~~python
label = ones_like(final_logit_weights)              # [B,4]
loss_l = binary_cross_entropy(final_logit_weights, label,
                              weight=reward[:,None])
loss_f = binary_cross_entropy(final_feature_weights, label,
                              weight=reward[:,None])
loss_agent = loss_l + loss_f                         # scalar
~~~

reward[:,None] 从 [B,1] 广播到 [B,4]。同一个样本的四个教师，使用同一个非负 reward。损失加在**融合后的最终分布**上，而不是只加在 learned head 上。

state 和 reward 都detach，agent_optimizer只含agent参数：

| 模块 | agent阶段是否产生新梯度 |
|---|---|
| 学生 | 否 |
| 特征适配器 | 否 |
| 教师 | 否 |
| agent，包括dynamic混合参数（如开启） | 是 |

代码中虽然有 get_actions 的二值阈值/随机补选函数，但这条 train 路径没有调用它。不能把未调用的辅助函数当作实际执行的教师离散采样。

## 13. 一个需要谨慎解释的数学后果

以下为**针对已核实代码目标的数学推导**，不是论文作者的实验结论。

对一个 reward>0 的样本、一个 head，标签全1的 BCE 等于：

\[
L_i=-\frac{r_i}{M}\sum_{m=1}^{M}\log w_{i,m},
\quad w_{i,m}>0,\quad \sum_mw_{i,m}=1.
\]

对一个可自由取值的概率向量，由凹性/Jensen不等式或拉格朗日乘子法，该目标在均匀分布 w_m=1/M 处最小，而不是直接告诉模型“奖励某个特定教师”。

M=3、r=1 时：

~~~text
uniform [.3333,.3333,.3333] → BCE 1.0986
peaked  [.8,.1,.1]         → BCE 1.6094
~~~

如果只有一个 learned softmax head，梯度对其分数为 r_i×(w−1/M)，会推向均匀。实际输出混合固定规则，learned head 又由共享网络产生，所以不保证所有最终权重都能达到均匀；规则仍可产生逐样本差异，参数约束与共享也会影响可达最优点。

**准确的表述：** 这个代码目标具有促进最终教师分布均衡的倾向，未显式表达旧动作与逐教师正负收益的对应；它不是清晰的 REINFORCE 实现。不能由此推断论文结果造假、所有权重都相等或完整方法一定无效。
