# MTKD-RL：代码核对、课题边界与备答

用途：配合 [约 29 分钟的主讲稿](report.md) 使用。以下是对论文与当前本地代码的静态阅读核对，本次没有重新训练或测量性能，也没有核验上游版本历史。

## 一、先固定三个角色

| 角色 | 输入/输出 | 是否训练 | 推理阶段 |
|---|---|---|---|
| 教师池 | 图像 → logits、特征 | 预训练后固定 | 可移除 |
| 学生 | 图像 → logits、特征 | 用监督损失和蒸馏损失训练 | 保留 |
| agent | 教师与师生状态 → 教师权重 | 单独优化、与学生交替 | 本文可移除 |

教师是知识来源，agent 是权重控制器。附录与代码将教师相关决策集成到一个双输出头网络；这不等于建立了有通信、协作或博弈机制的多智能体强化学习系统。

## 二、代码沿着数据走

### 1. 建立 agent 与特征适配器

`train_student_rl.py:164` 的 `get_agent()` 为各教师记录 `feature[-1].size(1) + logits.size(1) + 3`，然后构建 `PolicyTrans`。

`models/util.py:162` 的 `TransFeat` 对学生的最后一张特征图执行空间重采样，再用每位教师对应的 `Embed` 映射通道。`Embed` 包含 1×1 Conv、BN、ReLU。

代码默认训练末端特征图；不能据此说论文已经实现了浅、中、深三层多尺度蒸馏。

### 2. `get_agent_state()`：状态

定位：`train_loops.py:50`。

```python
feat_cos_sim = cosine_similarity(student_embedding, teacher_embedding)
logit_kl = criterion_div(student_logits, teacher_logits, unreduce=True)
teachers_ce = cross_entropy(teacher_logits, targets, reduction='none')
teacher_info = cat([
    feat_cos_sim, logit_kl, teachers_ce, teacher_embedding, teacher_logits
], dim=1).detach()
```

张量形状：每个教师 `teacher_info` 是 `[B, d_m + C + 3]`；教师 CE、师生 KL、师生余弦各拼成 `[B, M]`。

`.detach()` 阻断 agent 训练沿着状态构建路径更新教师、学生与特征适配器。

### 3. `PolicyTrans.forward()`：动作

定位：`models/policy.py:48`。

```python
all_teacher_infos = torch.cat(teacher_infos, dim=1)
hidden = self.steam(all_teacher_infos)     # Linear(total_dim, 128) + ReLU
w_gen_l = softmax(self.logit_head(hidden))
w_gen_f = softmax(self.feature_head(hidden))
w_conf = (1 - softmax(teacher_ce)) / (M - 1)
w_div_l = softmax(teacher_student_kl)
w_div_f = softmax(teacher_student_cos)
w_l = (w_gen_l + w_conf + w_div_l) / 3
w_f = (w_gen_f + w_conf + w_div_f) / 3
```

上面是关闭 `dynamic` 时的简化形式；开启时，用两组可学习的 softmax 系数分别融合三路权重。这里的系数是网络参数，不是额外读取场景的独立控制器。

两个动作都是 `[B, M]`。对于 `M>1`，三路权重均沿教师维度归一化；凸组合后每个样本的教师权重之和仍为 1。`M=1` 时可信度公式分母为零，当前实现不能无修改地用于单教师。

`get_actions()` 定义了阈值与随机选择逻辑，但当前 `train()` 并未调用它，不能把那段代码当成主训练的探索机制。

### 4. `train()`：学生更新

定位：`train_loops.py:179`，核心加权损失在第 255～274 行。

```python
loss_cls = CE(student_logits, labels)
loss_kd = sum(mean(w_l[:, m] * KL_i_m) for m in teachers)
loss_feat = feat_weight * sum(mean(w_f[:, m] * MSE_i_m) for m in teachers)
loss = loss_cls + loss_kd + loss_feat
loss.backward()
student_optimizer.step()
```

教师前向在 `torch.no_grad()` 中执行；动作也由 `no_grad()` 产生并 `detach()`。学生优化器包含学生及特征适配器，agent 使用另一个优化器。

`eval()` 主要改变 BN、Dropout 等模块行为，本身不关闭自动求导。这里靠 `no_grad()`、`detach()` 和不同优化器分开更新。

### 5. `DistillKL()`：别把 KL 参数方向讲反

定位：`utils.py:124`。

```python
log_p_s = log_softmax(z_s / T)
p_t = softmax(z_t / T)
loss = KLDivLoss(log_p_s, p_t) * T**2
```

PyTorch 此用法计算 \(D_{KL}(p_t\Vert p_s)\)，不是简单按函数传参顺序说成 \(D_{KL}(p_s\Vert p_t)\)。`unreduce=True` 保留每个样本的损失，才能施加样本级教师权重。

## 三、论文与当前代码：四处必须留意的差异

### 1. 奖励的粒度与归一化

论文 Eq.(6) 定义逐样本、逐教师奖励：

\[
R_i^m=-CE_i-\alpha KL_i^m-\beta MSE_i^m.
\]

论文 Eq.(8) 在 PDF 第 4 页实际印为：

\[
\bar R_i^m=
\frac{R_i^m-\min_k R_i^k}{\max_k R_i^k-\min_k R_i^k}
-\frac1M\sum_{k=1}^M R_i^k.
\]

第二项印的是原始奖励均值。正文用“min-max 归一化，再减均值”描述这个步骤，但如果奖励为负且先归一化项非负，减去原始负均值不会得到正文所说的正负相对反馈。因此，不应默默把原式改写成“减归一化后的均值”，然后声称那就是原文公式。还需考虑教师奖励相同导致分母为零的情况。

当前代码 `train_loops.py:277`～`290` 则把教师项加权合成每样本一个标量：

\[
r_i=-\left(CE_i+\sum_m w_{l,i}^mKL_i^m+
\beta\sum_m w_{f,i}^mMSE_i^m\right),
\]

随后沿 batch 的样本维度做标准化，并裁到 `[0,1]`：

```python
normalized_reward = ((reward - reward.mean()) / reward.std()).detach()
normalized_reward = torch.clamp(normalized_reward, min=0, max=1)
```

因此有三处区别：逐教师变成逐样本；跨教师 min-max 变成跨样本标准化；正负相对反馈变成非负权重。标准差为零时这里也未加 epsilon，应在复现时检查。

### 2. 奖励写在更新后，但没有重新前向

`optimizer.step()` 在 `train_loops.py:274`，奖励计算在第 277 行之后。不过奖励使用的仍是本 batch 更新前算出的 `logits` 和特征，未在参数更新后重新前向。

所以准确表述是：计算语句位于更新之后，使用的是之前缓存的输出。不能仅凭语句顺序就说它测量了“这一步更新带来的学生性能提升”。

### 3. `train_agent()` 并非标准随机 REINFORCE

定位：`train_loops.py:29`～`45`。

```python
pred_l, pred_f = agent(state)
label = torch.ones_like(pred_l)
loss_l = binary_cross_entropy(pred_l, label, weight=reward[:, None])
loss_f = binary_cross_entropy(pred_f, label, weight=reward[:, None])
```

缓存的 `actions` 在该函数中只用于统计 batch 大小，没有进入动作标签或 `log_prob`。策略主路径直接给出确定性 softmax 权重；没有显式构建连续动作概率密度、采样并计算该动作的对数概率，也没有 critic、Bellman 目标或目标 Q 网络。

对于某个非负奖励 \(A_i\)，单分支的该目标可写为：

\[
L_i=-\frac{A_i}{M}\sum_m\log w_i^m.
\]

若把最终权重视为可自由优化的概率向量，该目标在均匀权重时最小；这是由对数的凹性直接得到的性质。实际最终权重还受启发式三路融合约束，不能据此断言完整方法的权重会全部均匀或实验结果无效。但这说明它不能直接解释成“某位教师得到更高奖励，所以其已选动作概率提高”的标准动作信用分配。

原文 Eq.(7) 也直接写 \(\nabla_\theta\pi_\theta(s)\)，没有标准随机策略梯度中的 \(\nabla_\theta\log\pi_\theta(a\mid s)\)。汇报时把“作者描述的 PG 意图”“原文印出的公式”“当前代码的目标”明确区分。

**建议措辞**：

“方法通过学生侧反馈学习权重，作者将其归入策略梯度框架；但论文公式和当前实现存在不一致，不能完全按标准 REINFORCE 理解。复现时我会分别验证论文机制和代码机制。”

### 4. 更新频率与初始化

论文 Algorithm 2 按一个 epoch 收集历史，再遍历历史更新 agent。代码在 `batch_idx % agent_step == 0 and batch_idx != 0` 时更新，并在 epoch 末处理剩余缓存。`agent_step` 默认是 1000。

第 0 个 epoch 把动作覆写为全 1，保证教师等强度；策略训练仍复用当前 `train_agent()` 路径。不能说当前代码完整实现了独立的标准随机策略预训练阶段。

这些差异属于复现待核对事项；本次静态阅读没有验证其训练影响，也未对原代码作修改。

## 四、与老师课题连接时，先明确三个研究对象

| 研究对象 | 动作控制什么 | 奖励应主要评价什么 |
|---|---|---|
| 动态检测集合 | 融合输出、调用教师或传感器 | 集合检测质量与实际资源成本 |
| 自适应蒸馏 | 教师损失、层级强度、样本权重 | 学生侧学习收益及训练成本 |
| 部署期学生策略 | 学生分支、输入模态、计算路径 | 学生检测质量与部署开销 |

三种对象可以组合，但必须有清楚的控制路径和因果关系。多个教师的融合权重可以作为蒸馏参考，却不自动等于最适合学生的蒸馏权重。

### 1. DQN 与连续权重

标准 DQN 对有限离散动作估计 Q 值。若动作是任意四维连续权重，不能直接由标准 DQN 处理。

- 保留 DQN：定义 K 个权重模板，例如 RGB 优先、红外优先、均衡及其他组合；动作是模板编号。
- 保留连续权重：使用有明确连续策略定义的方法，如 PPO 配合 logistic-normal 或 Dirichlet 策略，或 DDPG/TD3/SAC 并对动作做约束映射。
- 离散到连续切换：需要说明后期换成哪个算法、怎样迁移参数及如何训练，不能只更改输出维度继续称 DQN。

上述是方法选项，不代表 PPO 必然优于简单门控。建议先建立门控网络对照。

Double DQN 是用在线网络选动作、目标网络评价该动作，目的是缓解 Q 值过估计。“评估网络 + 目标网络”本身也是普通 DQN 的常见结构，不能仅据此说明实现了 Double DQN，更不应称为“两套目标网络”。

### 2. mAP 奖励可以用，但评价窗口要合理

RL 不要求奖励可微，因此 mAP 的不可微性不构成禁用理由。困难是小 batch AP 方差大、类别覆盖不稳定、频繁评估昂贵。

可先用训练数据内部划出的固定反馈集、多个 batch 的场景窗口，或先用检测损失作为稠密代理再周期性检查 AP。用于策略奖励的数据属于训练流程，另保留独立验证与最终测试，不能反复用最终测试集选策略。

“0.7 × mAP - 0.3 × latency”前要明确量纲：AP 用 0～1 还是 0～100，延迟按哪个上限归一化，系数需由精度与速度的实际取舍及消融确定。

### 3. 延迟惩罚必须能被动作改变

如果四位教师每张图都运行完，策略才改融合权重，主要教师计算已经发生，改变权重通常不能明显节省这部分延迟。要优化集合推理开销，动作必须影响教师调用、传感器启用或计算路径，并计入获得状态的成本。

若最后只部署固定学生且不保留集合，教师集合延迟不能直接代表学生边缘推理延迟。可以把教师成本作为训练预算约束，学生延迟则在固定硬件测量；或设计真正影响学生计算路径的策略。

### 4. 单学生的输入模态先确定

“单模型”不等于“单模态”。学生可以只接 RGB，也可以接 RGB-红外或三模态，但传感器成本、预处理和部署路径不同。

若学生只看 RGB，教师在夜间从红外/雷达获取、RGB 中完全不存在的信息无法保证被恢复。应检验可迁移的相关信息与性能上限，而不是承诺通过蒸馏弥补所有模态缺失。

### 5. 特征与检测输出对齐

- RGB-红外需要同步、空间配准，并明确遮挡、视角差异的处理。
- 雷达稀疏点与图像特征不能直接逐像素求 MSE；需标定投影、BEV 或目标级表征等可比较空间。
- 不同检测器的候选框/查询没有天然逐项对应；分类、回归蒸馏前要定义匹配、分配或公共监督位置。
- 对齐通道和分辨率只是必要的计算准备，不足以保证语义对应。

论文采用逐教师损失加权，可作为先建立简单方案的思路；若要先融合教师特征，应另说明公共空间与融合有效性。

### 6. “动态决策知识迁移”要有监督或证据

学生被动态教师监督，说明知识来源随场景变化；还不能直接证明学生复现了策略网络的决策行为。场景调制模块也只是提供相应能力。

一种待验证设计：学生由自己的部署输入生成 \(\hat w(x^S)\)，在训练阶段模仿冻结教师策略给出的 \(w^T\)，加上策略分布匹配损失。但只有教师策略相关信息能由学生输入预测时，这种迁移才有希望；仍需比较有无策略监督、普通注意力模块及相同参数预算。

### 7. 数据与参考文献

FLIR、KAIST 可作为相关 RGB/热红外检测数据的调研起点，但并不能据此视为同步 RGB-红外-毫米波雷达三模态数据。KAIST 主要面向行人，类别与轨行区障碍物需要重新匹配。不同数据集不能靠统一标注格式变成真实配对的三模态样本。

视频数据按序列、地点或采集时段划分，避免相邻帧跨训练/测试带来泄漏。天气等级、目标密集度等部署期状态需来自可获取输入或预测，不能依赖测试标签。

老师方案末尾五个英文参考题目目前缺作者、年份、会议/期刊与 DOI/arXiv 标识；本次没有联网核验其存在性。可先作检索线索，不要当作已核实论文写入正式参考文献；也不能据此断言它们不存在。

## 五、老师可能问的 12 个问题

**1. 这篇论文最核心的创新是什么？**

结合教师表现、师生差距和学生反馈，学习样本级多教师蒸馏权重；输出与特征两种知识分别加权。主贡献在决策框架与信息设计。

**2. 为什么要用强化学习？直接学一个门控网络不行吗？**

可以。作者希望利用动作之后的学生反馈来优化权重，文中实验表明其完整方法具有竞争力。不过“必须用 RL”还需要相同条件下的可学习门控、启发式融合和真正有信用分配的策略对照才能证明。我会把这些放进自己的实验设计。

**3. 它用 DQN 吗？**

主方法采用作者称为 Policy Gradient 的方案，比较了 PG、PPO、DPG、DDPG。它直接输出连续权重，当前主路径没有 Q 网络或 Bellman 更新。

**4. 状态里哪里体现学生？**

学生通过与每位教师的特征余弦相似度和输出 KL 进入状态。学生不断更新，这两项随之变化。

**5. 教师越强，权重一定越大吗？**

不一定，整体准确率不等于样本表现，也不等于适合当前学生。完整权重还受到匹配程度和网络生成部分的影响。

**6. 为何两套权重？特征和输出的差距方向为什么不同？**

特征希望语义更匹配以便模仿；输出分支的启发式希望加强对尚未对齐的概率知识的学习。因此作者分别设计权重。它是具体设计动机，其有效性仍应由实验支撑。

**7. 学生推理还要调用教师和 agent 吗？**

本文的蒸馏权重只在训练阶段使用，测试代码只调用学生。自己的方案若保留在线调制模块，则需要计入学生完整推理路径。

**8. 检测实验能直接作为我课题的基线吗？**

可以借鉴迁移结果与权重框架，但 Table 4 是蒸馏预训练骨干迁移到检测，不包含自己的多模态检测头蒸馏。需要另建端到端检测基线。

**9. 这个奖励真的表示学生进步了吗？**

原文用负损失评价学生侧表现，是代理指标。当前代码未重新前向测量更新后的收益，也没有直接度量验证集增益，因此不能把奖励称为已验证的学习进步量。

**10. 为什么不让教师也一起训练？**

固定教师提供较稳定的知识目标，减少变化来源，也使教师质量和学生收益更容易比较。联合训练是另一个设计，需要说明教师监督、稳定性与额外成本。

**11. 四位教师是否足够？三种模态为何是四个智能体？**

教师数量与模态数量是不同维度。可有不同模态组合，也可有同模态不同专长；是否互补要看错误重叠、尺度/天气子集表现及集合增益。论文的四教师饱和结论只来自其具体实验。

**12. 你准备怎样开始自己的课题？**

先训练检测学生与两个教师，跑通单教师、等权多教师、普通门控、RL 加权四类对照；统一数据、输入与损失。然后引入配准 RGB-红外，验证昼夜与退化子集收益；待数据条件清楚后增加雷达与策略迁移。用真实硬件单独测完整学生延迟与峰值内存。
